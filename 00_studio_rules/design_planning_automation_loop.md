# Design Planning Automation Loop

## Purpose

This rule defines how Loop Mission should automate planning before design and implementation.

## Planning Loop

1. Intake
2. Reference analysis
3. Product goal definition
4. Creative brief
5. Visual direction options
6. Image prompt pack
7. Design concept review
8. Build spec
9. Codex implementation task
10. QA review
11. Learning update

## Intake Fields

- loop type
- target audience
- reference source
- desired output
- visual style
- platform
- monetization goal
- technical constraints
- iteration size

## Planning Output Types

- creative brief
- design prompt pack
- image to build spec
- implementation task
- review scorecard
- learning update

## Planning Quality Rules

A good automated plan should be specific, buildable, visually directed, scoped to one iteration, compatible with repo structure, easy for Codex to execute, and easy for the user to review.

## Avoid

- vague inspiration lists
- unbuildable fantasy descriptions
- overly broad MVP scope
- mixing web and Unity tasks in one implementation diff
- claiming visual quality without design evidence

## Approval Rule

For visual-heavy decisions, produce options and wait for selection when possible. If running unattended, select the safest option and label it as an auto-selected draft direction.
